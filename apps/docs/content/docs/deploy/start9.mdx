title: 'Start9 Deployment'
description: 'Run LaWallet NWC on your Start9 server (StartOS) as a self-contained app.'
---

[StartOS](https://start9.com) is the sovereign-server OS behind Start9. LaWallet
NWC ships as a StartOS **service package** (`.s9pk`) that bundles the web app,
NWC listener, and its own PostgreSQL database into one installable app —
nothing external to wire up. It wraps the same published images as every other
target: [`masize/lawallet-nwc`](https://hub.docker.com/r/masize/lawallet-nwc)
and [`masize/lawallet-nwc-listener`](https://hub.docker.com/r/masize/lawallet-nwc-listener).

There are **two package tracks** with the same package id (`lawallet-nwc`).
They are not interchangeable:

| Track | Repo | Volume layout | How you install |
| ----- | ---- | ------------- | --------------- |
| Start9 Community | [`Start9-Community/lawallet-startos`](https://github.com/Start9-Community/lawallet-startos) | `main` (app data) + `db` (Postgres dump) | Community marketplace |
| Sideload | [`lawalletio/lawallet-startos`](https://github.com/lawalletio/lawallet-startos) | Postgres on `main` subpath `postgresql` | Download the `.s9pk` |

Do **not** switch an existing install from one track to the other. Same
package id, incompatible data directories — uninstall and start fresh, or
restore a backup taken on the same track.

| Property      | Value                                                                                  |
| ------------- | -------------------------------------------------------------------------------------- |
| Package id    | `lawallet-nwc`                                                                         |
| Images        | `masize/lawallet-nwc` + `masize/lawallet-nwc-listener` + `postgres:15-alpine`           |
| Architectures | `x86_64`, `aarch64`                                                                    |
| Web UI        | port `2288` (LAN, `.local`, Tor, or a custom domain)                                     |

## Install from the Start9 Community registry

The Community listing is the supported path for new StartOS installs. Open
**Marketplace → Community** and install **LaWallet NWC**.

The listed wrapper `2.0.0:1` predates the NWC vault. LaWallet NWC 2.6.0 and
later need a persisted `NWC_VAULT_SECRET` on both web and listener — without it
the Payment Listener stays unhealthy. The Community update that adds that key is
[`Start9-Community/lawallet-startos#2`](https://github.com/Start9-Community/lawallet-startos/pull/2),
which is still in review in that registry.

**Until it merges, install the sideload package below instead.** Do not bump the
listing's image tags by hand: the app will start, and the listener will exit on
boot because the vault key it requires was never generated.

## Sideload the current release

Use this if you already sideloaded from lawalletio, or if you need a `.s9pk`
before the Community update publishes:

1. Download the universal package —
   [`lawallet-nwc.s9pk`](https://github.com/lawalletio/lawallet-startos/releases/latest/download/lawallet-nwc.s9pk).
   It supports both `x86_64` and `aarch64` StartOS servers. You can also choose
   a specific version from the [release history](https://github.com/lawalletio/lawallet-startos/releases).
2. In the StartOS dashboard, open **System → Sideload a Service**, select the
   downloaded `.s9pk`, and complete the install.
3. Start the service. Postgres starts first; once it is ready, the web app
   applies pending Prisma migrations and starts automatically.
4. Open the service's **Web UI** from the StartOS dashboard.

The sideload package was migrated to **start-sdk 2.0** in
[`lawalletio/lawallet-startos#2`](https://github.com/lawalletio/lawallet-startos/pull/2):
it no longer regenerates secrets when `store.json` is missing, it persists the
NWC vault key, and it keeps Postgres on the `main` volume so existing installs
keep their data.

That revision ships with the **v2.7.0** package and later. The `v2.6.0` asset
predates it — a `.s9pk` is only built when a release is published, and the SDK
migration merged after `v2.6.0` was cut. Take the newest release, not `v2.6.0`.

## Build the package yourself

Build from [`lawalletio/lawallet-startos`](https://github.com/lawalletio/lawallet-startos)
when you need to inspect or change the sideload package. The build machine needs
the [StartOS SDK](https://docs.start9.com/), including `start-cli`, plus
Node.js, Docker, and `make`.

```bash
git clone https://github.com/lawalletio/lawallet-startos.git
cd lawallet-startos
npm install
make universal
```

This produces `lawallet-nwc.s9pk`, a universal package that you can upload
through **System → Sideload a Service** as above. To make separate
architecture-specific packages instead, run `make`; it creates
`lawallet-nwc_x86_64.s9pk` and `lawallet-nwc_aarch64.s9pk`.

For a StartOS host already configured for the SDK, `make install` builds and
sideloads the package directly. See the package repository for its current
[build and update details](https://github.com/lawalletio/lawallet-startos#building).

## First run — claim root

There is **no admin password**. LaWallet NWC authenticates with **Nostr**:

1. In the Web UI, sign in with a **NIP-07 browser extension** (Alby, nos2x) or
   by pasting your **nsec**.
2. The first user to sign in claims the **root admin** role — do this
   immediately.
3. Set your domain, create lightning addresses, connect a remote wallet (NWC),
   and issue cards from the dashboard.

## Make lightning addresses resolve on your domain

LaWallet NWC serves public `.well-known` endpoints that your domain must
forward to the service so lightning addresses and Nostr identity resolve.
The onboarding wizard probes these three:

- `/.well-known/lnurlp/<username>` — LUD-16 lightning address callback
- `/.well-known/nostr.json` — NIP-05 identity
- `/.well-known/lawallet.json` — instance discovery

LUD-21 payment verification still lives at `/.well-known/verify`. Forwarding
the whole `/.well-known/` prefix (the recipes the wizard prints) covers that
path too.

Point your domain at the StartOS interface for the service. The in-app
onboarding wizard prints copy-paste rewrite recipes (Cloudflare, Nginx, Caddy,
Vercel, and more).

## What's managed for you

The package generates and persists six independent secrets on first install
and sets the runtime environment automatically. Sideload stores them on the
`main` volume; Community stores them on `main` and dumps Postgres from `db`.

| Variable                        | Value                                                        |
| ------------------------------- | ------------------------------------------------------------ |
| `DATABASE_URL`                  | bundled localhost Postgres                                   |
| `JWT_SECRET`                    | generated on install                                         |
| `KEY_VAULT_SECRET`              | encrypts server-custodied Nostr keys; independent of NWC   |
| `LISTENER_AUTH_SECRET`          | generated once; shared by web/listener                      |
| `LISTENER_REQUEST_AUTH_SECRET`  | generated once; web→listener bearer, distinct from webhook   |
| `NWC_VAULT_SECRET`              | encrypts RemoteWallet/proxy NWC data; shared by web/listener |
| `LISTENER_URL`                  | private bundled listener                                     |
| `NODE_ENV`                      | `production`                                                 |
| `PORT` / `HOSTNAME`              | `2288` / `0.0.0.0`                                           |

Do not reuse `KEY_VAULT_SECRET` as `NWC_VAULT_SECRET`. They encrypt different
data.

Existing installs are upgraded safely: if the listener-request or NWC vault
secrets are missing from an older `store.json`, the package generates and
persists them once. Postgres and JWT secrets are never regenerated. Configure
the NIP-57 receipt signer `nsec` in **Admin → Settings → NWC Services**. It is
encrypted with the generated vault key and is not a StartOS environment
variable.

The web startup pass encrypts any legacy plaintext RemoteWallet NWC rows before
its health check becomes ready. The listener waits for that health check and
uses the same generated key.

For the full env-var reference (used when self-hosting outside StartOS), see
[`apps/web/.env.example`](https://github.com/lawalletio/lawallet-nwc/blob/main/apps/web/.env.example).

## Health & backups

- **Health check:** the service reports healthy once `GET /api/health` responds
  (it verifies the database connection). The Payment Listener has its own
  check on `GET /health`.
- **Backups:** restore only a backup taken on the same package track. Sideload
  captures the `main` volume (Postgres files, app data, secrets). Community
  dumps Postgres logically from `db` and copies `main`.

## Limitation

The bundled landing screen links to `https://lawallet.io` (baked into the
published image at build time). Your admin dashboard and wallet work regardless.

## Updating

Sideload image tags plus package version are bumped automatically when LaWallet
NWC publishes a release — see
[UPDATING.md](https://github.com/lawalletio/lawallet-startos/blob/master/UPDATING.md)
in the sideload package repo. Community listing updates go through
[`Start9-Community/lawallet-startos`](https://github.com/Start9-Community/lawallet-startos).
