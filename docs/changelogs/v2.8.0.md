# v2.8.0

![LaWallet v2.8.0 — Faster. Steadier. Leaner.](https://raw.githubusercontent.com/lawalletio/lawallet-nwc/main/docs/changelogs/assets/v2.8.0.png)

## Release date

2026-10-12

## Summary

This is a **stability and speed** release, driven by production data. A Sentry
triage of beta.lawallet.io turned up a crash that took down the wallet on
screen changes, plus a set of slow paths: a 4.3s wallet first paint, profile
lookups blocked on Nostr relays for seconds, and a listener tick that woke the
web app 129k times a month even when there was nothing to do.

The crash came from **Chrome's page translation** rewriting text nodes that
React owns. On the next navigation React tried to move nodes that no longer
existed and the whole app fell back to "Something went wrong" (#333). The page
now opts out of translation, and every wallet and admin screen has its own
error boundary, so one failing screen no longer takes the app down (#335).

The rest is a performance pass across the stack, shipped as 14 focused PRs
(rolled up in #338 and #348):

- **A lighter, faster wallet start.** A valid session renders immediately and
  is checked in the background, and the root JS bundle is 19% smaller (#347).
- **No more waiting on relays.** Profiles and NIP-05 serve what's cached and
  refresh in the background (#341).
- **Leaner servers and database.** Fewer queries per request, cached settings,
  new indexes, a sized connection pool, and a cheap cold start (#342, #345,
  #346, #337).
- **A faster payer path.** LUD-16 lookups drop unused queries and become CDN
  cacheable (#340).
- **A listener that idles when idle,** plus invoice expiry and data retention
  (#343).
- **Fewer re-renders and background polls** in the wallet and admin, and a
  hardened service worker (#344, #339).

## Heads-up before upgrading

These change behaviour. None needs action unless you want to opt out.

### Data retention is on by default (#343)

Rows older than **90 days** are now deleted from `ActivityLog`,
`ForwardingHop`, and finished (`SUCCEEDED`/`EXPIRED`) notification deliveries,
at most once an hour, in batches. Delivery rows are never pruned below 31 days,
because they double as the listener's replay dedup key.

**To keep everything, set this on the web app before you deploy:**

```bash
DATA_RETENTION_DAYS=0
```

The listener also prunes finished `listener.nwc_requests` rows older than 30
days. Pending and unknown requests are never pruned.

### Stale invoices now become EXPIRED (#343)

Ordinary `PENDING` invoices more than an hour past `expiresAt` move to
`EXPIRED`. Before, only proxy and claim invoices ever expired, so the pending
set — and every settlement sweep over it — grew forever. Proxy invoices keep
their own state machine. Every reader of invoice status was audited for the new
value.

### Browser page translation is disabled (#333)

The app sets `translate="no"` and `<meta name="google" content="notranslate">`.
Users who relied on Chrome's automatic translation will see the original
(English) UI. Patching React to tolerate translation was rejected: translated
balances could go stale without anyone noticing, which a wallet can't afford.

## Highlights

### Crash fixes and resilience

- Page translation no longer crashes the app. Sentry LAWALLET-WEB-T/S/F/V, 70
  events across every screen (#333).
- Route error boundaries for `/wallet` (app and onboarding) and `/admin`. A
  failing screen shows "Try again" / "Go home" inside the wallet shell or admin
  sidebar, and is reported to Sentry (#335).
- The admin no longer redirects to `/admin` on a single failed health check,
  which used to lose unsaved forms. It now needs two consecutive failures,
  ignores them while offline, and shows a banner instead (#344).

### Wallet speed

- **Optimistic sign-in:** a stored, unexpired JWT marks the session
  authenticated straight away and is validated in the background. Only a real
  401/403 logs you out. A network error, timeout or offline launch no longer
  bounces you to the landing page or into a reload loop (#347).
- **Smaller bundle.** `@nostrify/nostrify` and the signer dialog (with its QR
  code library) load on demand, the 220 KB treasure-chest animation is only
  preloaded by the screens that play it, and its 1.2 MB player wasm is
  self-hosted. Root-layout first-load JS goes from **327 KB to 266 KB (−19%)**;
  `/wallet` from 379 KB to 345 KB (#347).
- **No brand-colour flash:** the community theme is applied before first paint
  (#347).
- **Fewer re-renders.** Server events re-render only the hooks subscribed to
  that event type. The balance provider is memoised and no longer flips
  `loading` on background polls. Exchange rates come from one shared Yadio
  store (60s TTL, deduped) instead of one loop per component (#344).
- **Quieter in the background.** Balance, Connection Map, Yadio and admin
  health polls pause while the tab is hidden and refresh when it returns (#344).
- **Leaner prefetching.** Only the main tabs are prefetched, nothing is
  prefetched on Save-Data, the QR scanner (`@zxing`, ~108 KB gz) loads on
  demand, and activity rows are no longer prefetched one by one (#344).

### Nostr profiles and NIP-05

- `POST /api/nostr/profiles` serves cached profiles immediately and refreshes
  stale ones in the background with `after()`. It only waits on relays for a
  profile it has never seen, and then for at most 3s. In production this route
  ran at p50 3.1s, with `relay.nostr.band` reaching p95 121s (#341).
- A not-found profile is remembered for 10 minutes instead of re-querying
  relays on every request. Forced refreshes are limited to admins (#341).
- `/.well-known/nostr.json` serves the stored relay list, refreshes it in the
  background, and is CDN-cacheable (`s-maxage=300`) (#341).

### Payments (LUD-16 / LUD-21)

- The payRequest lookup drops a primary-wallet query it never used and an nsec
  decrypt it only needed for a pubkey. The remaining reads run in parallel and
  the response is CDN-cacheable for 60s (#340).
- The inline avatar in payRequest metadata is capped at about 32 KB instead of
  256 KB (#340).
- The callback reads the primary wallet only on the failure path, and the
  LNCurl auto-heal call has an 8s timeout (#340).
- LUD-21 verify is rate-limited and throttles its NWC `lookup_invoice` to once
  every ~5s per invoice (#340).
- Address protocol badges load the proxy config and zap capability once per
  request instead of once per address. The NWC client cache is LRU-capped and
  closes evicted relay sockets (#340).

### Server and database

- **Each request resolves its account once.** About 78 routes re-ran the same
  lookup that authentication had just done (#345).
- **Settings** are served from a 15s hot snapshot for anonymous and wallet
  reads. Admin reads stay fresh, and backup restore now invalidates the cache
  (#345).
- The **OpenAPI** document is built once per process (#345).
- **Activity log writes** are kept alive with `after()`. On Vercel they used to
  be frozen mid-write and delayed or lost (#345).
- **Cheap cold start.** The NWC vault migration exits with a single `EXISTS`
  probe when there is nothing to migrate. Before, it walked and decrypted every
  wallet under an advisory lock on every boot. When work exists it pages by id
  (#342).
- **Connection pool** sized for serverless (3 connections per instance on
  Vercel, 10 elsewhere) with connect and idle timeouts. Prisma query logging
  is only wired up when it will print (#342).
- **Indexes:**
  - partial indexes for the zap settlement and receipt sweeps
  - indexes on unindexed foreign keys (`RemoteWalletForwardReceipt`)
  - lookup indexes: `Card.otc` (public route), `Voucher.merchantPubkey`,
    `ProxyPayment(status, createdAt)` and more
  - nine redundant or unused indexes dropped
  - the six card counts are now a single scan (#346)
- **Fewer profile-cache writes:** they are batched into one transaction instead
  of one upsert per pubkey (#337).

### Listener

- **Adaptive zap tick.** The settle endpoint now reports whether work is
  pending. The listener ticks every 20s while it is, backs off to 5 minutes
  while idle, and snaps back on a `payment_received`. An older web app keeps
  the old fixed cadence (#343).
- **Catch-up concurrency** is capped at 8 wallets, and liveness entries for
  removed wallets are cleaned up (#343).

### Real-time (SSE) and PWA

- **SSE `/api/events`:**
  - streams recycle cleanly before the platform limit
  - slow clients are dropped instead of buffered without limit
  - reconnects add jitter and refetch whatever was missed
  - `invoices:updated` can be scoped to the invoice owner (#344)
- **Service worker:**
  - never caches a failed chunk, which caused sticky `ChunkLoadError`s after a
    deploy
  - trims old static assets
  - stops waiting on the network after 3.5s when launching, and serves the
    cached shell instead
  - starts API fetches without waiting on the cache
  - keeps the app shell and animation cache on logout (#339)

### Observability

- Sentry drops third-party noise: the Vercel Live toolbar, browser extensions
  and MetaMask (#336).
- The listener reports expected relay and wallet failures as fingerprinted
  warnings, one quiet issue per kind and relay, instead of floods of errors.
  Sentry LAWALLET-LISTENER-1/2/4/5 (#334).
- Traces are no longer sampled for SSE and are sampled at 5% for LUD-16 and
  `/.well-known` (#342).

### Build and CI

- PR checks (CI, E2E, security) now run for PRs into any branch, not only
  `main`, so integration branches get gated too (#338).
- Unused dependencies removed: `html5-qrcode`, `qr-scanner`,
  `react-qr-scanner`, `use-nfc-hook`, `websocket-polyfill` (#344).

## Upgrading

Migrations run automatically on start for Docker, Umbrel, and Start9. This
release adds `20261012172246_perf_db_indexes` (index changes only, no data
changes).

New **optional** environment variables. All have defaults, and the Umbrel and
Start9 env contracts are unchanged:

| Variable                     | Where    | Default              | Purpose                                         |
| ---------------------------- | -------- | -------------------- | ----------------------------------------------- |
| `DATA_RETENTION_DAYS`        | web      | `90`                 | History retention; `0` disables pruning         |
| `DATABASE_POOL_MAX`          | web      | 3 on Vercel, else 10 | Postgres pool size per instance                 |
| `DATABASE_URL_UNPOOLED`      | web      | `DATABASE_URL`       | Direct (non-PgBouncer) URL for `prisma migrate` |
| `ZAP_SETTLE_MAX_INTERVAL_MS` | listener | `300000`             | Longest idle gap between zap settlement ticks   |

Redeploy the listener as well to get the adaptive zap tick. Any mix of old and
new web and listener versions keeps working.

Umbrel and Start9 packages are bumped by automation once the images publish.
