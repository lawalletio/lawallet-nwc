# v2.7.0

## Release date

2026-09-11

## Summary

Zap receipts now work with **every** NWC wallet. NIP-57 settlement used to
depend on the wallet pushing a `payment_received` notification, but
`notifications` is optional in NIP-47 — so a wallet that implements none left
every zap invoice `PENDING` and its `kind:9735` receipt unpublished, on an
address that advertised `allowsNostr`. The listener now ticks a sweep that asks
those wallets directly with `lookup_invoice` (#261).

The other headline is **vouchers**: a coupon stash compatible with the
[lacrypta/coupons](https://github.com/lacrypta) protocol, so an operator can
hand out claimable value that lands in a user's wallet (#163).

Beyond that this is a large hardening release — 72 merged PRs, most of them
fixes. A dedicated security pass closes a TOCTOU card-key leak, a pubkey
existence oracle, a cleartext bearer-token log, and several observability
leaks. Payment forwarding, BoltCards, webhook delivery, and the wallet UI each
got a round of correctness work.

Two integrations were **removed**: the unused Alby Hub sub-account path and the
legacy `subdomain` setting. Both ship migrations — read the Breaking changes
section below before upgrading.

## Breaking changes

### The Alby Hub sub-account integration is gone (#262)

Courtesy wallets have been provisioned through LNCurl and stored as
`RemoteWallet` rows for several releases; the Alby Hub path was dead code that
still carried an admin bearer token. It is now removed along with its HTTP
client, signup auto-provisioning, and its API, settings, and backup surface.

Migration `20260910120000_drop_alby_hub` drops the `AlbySubAccount` table and
the `User.albyEnabled` column, and deletes the `alby_api_url`,
`alby_bearer_token`, and `alby_auto_generate` rows from `Settings`.

**If you set any of these, delete them — they are no longer read:**

```bash
ALBY_API_URL
ALBY_BEARER_TOKEN
AUTO_GENERATE_ALBY_SUBACCOUNTS
```

Backups taken before this release still restore: `AlbySubAccount` rows are
simply skipped.

### The legacy `subdomain` setting is folded into `domain` (#161)

The public host used to be composed as `<subdomain>.<domain>`, and address
resolution kept preferring that pair over `endpoint`. Migration
`20260819120000_drop_legacy_subdomain_setting` concatenates a non-empty
`subdomain` into `domain` before deleting the row, so the address host and the
public endpoint stay byte-identical. Dropping the row without that step would
have silently re-labelled every lightning address on those instances.

A blank `subdomain` contributed nothing already and is just deleted. A blank
`endpoint` now defaults to `https://<domain>`.

### Node 24 is required to build (#265)

`.nvmrc` moves to **v24.21.0** and the repo is on **pnpm 11**. This affects
contributors and anyone building images locally; published Docker images are
unaffected.

## Highlights

### Zaps and NIP-57

- Zap receipts for every NWC wallet, via a `lookup_invoice` settlement sweep the
  listener wakes on a timer — new `ZAP_SETTLE_INTERVAL_MS` on the listener,
  default `20000`, `0` disables. Web still owns candidate selection, so a
  compromised ping cannot steer it at a chosen row (#261)
- Include the sender `P` tag on `kind:9735` receipts (#246)

### Vouchers

- Coupon stash compatible with the lacrypta/coupons protocol, with per-instance
  `allowVouchers`, a deposit policy, and a sender allowlist (#163)
- Correct the `p` tag semantics in the voucher event verification list (#238)

### Security

- Make BoltCard write-token consumption atomic, closing a TOCTOU window that
  could leak card keys (#215)
- Close the 403/404 pubkey-existence oracle on
  `PUT /api/users/[userId]/relays` (#222)
- Stop logging the Alby Hub admin bearer token in cleartext (#218)
- Scrub `event.tags` and redact bearer-token path segments in Sentry (#216), and
  apply the same scrubbing to transaction events, not just errors (#245)
- Strip database transaction timing from Prisma error messages (#235)
- Honor the `settings.root` fallback in the NIP-98 admin maintenance bypass
  (#214)
- Fail closed on device-token verification when no endpoint is configured (#226)
- Thread the request into the LUD-16 `ALIAS` cycle detector to block
  same-instance reentry (#221)
- Return 503 instead of leaking internals when a remote-wallet vault decrypt
  fails (#253)
- Bump Next.js to 16.3.4 and clear the Dependency Audit gate (#237)

### Payments, forwarding, and remote wallets

- Keep residual routing-reserve legs when editing a receive config (#248)
- Pause forwarding before the `isDefault` early return (#212)
- Pass `walletActive` into the user Remote Wallet panel (#217)
- Hide revoked and dead wallets from the admin forwarding map (#242)
- Treat `settled_at: 0` as pending in `lookupInvoice` (#224)
- Decrypt the bound `remoteWallet` before the NWC lookup in verify (#225)
- Bind the LNCurl primary address inside the create transaction (#256)
- Flag view-only NWC connections instead of calling them receive-only (#254)
- Guard `useNwcBalance` against stale concurrent `getBalance` fetches (#223)
- Return 400 for invalid LUD-16 proxy callback amounts (#258)
- Report why a paid registration mint failed instead of dead-ending on the 402
  (#164)

### Cards

- Only promote a MASTER card if it still belongs to the holder (#247)
- Stop a stale RECEIVE mode from permanently blocking card spends (#162)
- Scope card-design import dedup to fetched catalog IDs (#213)
- Attribute card-design `PUT` updates to the acting user in the audit log (#219)

### Listener and webhooks

- Keep the webhook sweep from overlapping inline retries (#243)
- Time out webhook DNS and retry lookup failures (#250), with coverage for the

- Suppress retryable NWC warmup errors from Sentry (#170)

### Wallet and admin UI

### Auth and Nostr

## Upgrading

Nothing to do beyond the usual deploy — migrations run automatically on start
for Docker, Umbrel, and Start9. Remove the three `ALBY_*` variables if you set
them.

Umbrel and Start9 packages are bumped by automation once the images publish.
Start9 operators on the **Community registry** listing should stay on the
sideload `.s9pk` until that listing adopts the v2.6.0 secret contract — see
[Start9 deployment](https://docs.lawallet.io/docs/deploy/start9).
