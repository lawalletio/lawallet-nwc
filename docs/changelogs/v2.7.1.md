# v2.7.1

## Release date

2026-09-21

## Summary

Wallet receive and activity get the same receipt treatment as send, with a
live payment cue on incoming settlements. The listener image copies
`packages/shared/node_modules` so tsup can resolve its OpenAPI dependency at
build time. StartOS sideload and Community listings now share one `main` +
`db` layout; we document that, gate the owned package so it cannot regress,
and open Community-registry PRs instead of asking Start9 to pull our tree.

## Highlights

### Wallet

- Realtime payment cue and balance animation when a settlement lands (#298)
- Activity rows open on the same receive/send-style receipt as the live
  flows (#296)
- Receive amount reuses send's currency switch (#297)

### Listener

- Copy `packages/shared/node_modules` into the Docker build so the published
  image can resolve `@asteasolutions/zod-to-openapi` (#291)

### Start9

- Sideload `2.7.0:1` (and this wrap) uses Community's `main` + `db` volumes
  and `withPgDump()` backups. Updating from sideload `2.7.0:0` copies
  `main/postgresql/data` onto `db` once.
- `deploy:check` requires that layout on `lawalletio/lawallet-startos`.
  `Start9-Community/lawallet-startos` stays advisory: registry builds are
  made only from that fork, via PRs the sideload Release workflow opens.

## Upgrading

Nothing to migrate in the app itself.

Start9 operators on sideload `2.7.0:0` should update to `2.7.0:1` or this
`2.7.1:0` package so Postgres moves onto `db`. Community-registry installs
wait for [Start9-Community/lawallet-startos#5](https://github.com/Start9-Community/lawallet-startos/pull/5)
(or a later overlay PR) to merge — do not expect that repo to pull
lawalletio on its own.
